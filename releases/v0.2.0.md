# v0.2.0

## Breaking MCP tool schema changes

None. Existing tool names, required parameters, and existing response fields are preserved.

## Changes

- Add `vsphere_query_metric_samples` for actual performance readings with aligned timestamps, sampling intervals, units, and scales. Use `vsphere_query_metrics` to discover counter names, then request CPU, memory, disk, or network samples for a VM or host. Percent readings use a scale of `0.01`.
- Add `vsphere_get_resource` for resource identity, status, and selected VM, host, and datastore summaries.
- Add `vsphere_list_triggered_alarms` when alarm queries are supported. The existing alarm tool continues to return alarm definitions.
- Add inventory names and paths, offset pagination, exact-name filtering, and datacenter selection while preserving the original inventory object types.
- Add entity and time filters to event and recent-task queries; filter before applying the result limit and return recent tasks by queue time, newest first.
- Report authentication, permission, and temporary capability-query failures accurately. Release query-owned inventory views after cancellation and close the session when startup capability detection fails.
- Update English and Chinese documentation with a VM monitoring workflow, sampling examples, and query limitations.

## Query limitations

- Sampling defaults to the provider's real-time refresh rate and one point per series. Historical intervals and retention depend on the target's collection settings. Empty readings remain empty.
- Time filters use server time. Inventory changes between offset pages can shift results.
- Task queries read the target's recent-task cache, not arbitrary task history. Failed sessions require restarting the MCP server; automatic reconnection is not added.
- Read-only monitoring queries were smoke-tested on ESXi 6.7. vCenter-specific event and alarm behavior was checked with simulators, not a live vCenter deployment.

## 更新

- 新增 `vsphere_query_metric_samples`，返回实际监控采样值、对应时间、采样间隔、单位和换算比例。先用 `vsphere_query_metrics` 查找指标名称，再查询 VM 或主机的 CPU、内存、磁盘或网络数据；百分比原始值乘以 `0.01`。
- 新增 `vsphere_get_resource`，查询资源身份、状态及 VM、主机、数据存储的选定摘要。
- 支持告警查询的目标新增 `vsphere_list_triggered_alarms`，查询当前触发的告警；原告警工具继续返回告警定义。
- 清单增加名称、路径、偏移分页、精确名称筛选和数据中心选择，并保留原有资源类型。
- 事件和近期任务增加资源与时间筛选，先筛选再限制条数；近期任务按排队时间倒序返回。
- 如实报告认证、权限和临时能力查询错误；请求取消后释放查询创建的清单视图，启动能力检测失败时关闭会话。
- 中英文文档补充 VM 监控流程、采样示例和查询限制。旧工具名、必填参数及已有返回字段保持兼容。

## 查询限制

- 默认按目标的实时采样间隔返回每组数据的最近一个点；历史采样间隔和保留范围由目标配置决定。缺失采样不会伪造为零。
- 时间筛选使用服务端时间；清单变化可能使偏移分页结果移动。
- 任务查询使用目标的近期任务缓存，不支持任意历史任务查询。会话失效后需重启 MCP 服务，本次未增加自动重连。
- 只读监控查询已在 ESXi 6.7 上完成实测；vCenter 专有事件和告警行为通过模拟器验证，尚未在真实 vCenter 上验证。
